## 第一阶段 — 基础设施与薄弱模块（2026 年 4 月）

**目标里程碑：M1**

### 支柱 4：新手引导

- [ ] **T-001** — 编写 `scripts/quickstart.sh`
  - 检测 `~/.claude/` 目录（缺失时经用户确认后创建）
  - 将首个 slash command + CLAUDE.md + skill 复制到用户配置中
  - 在 CLAUDE.md 中追加 agent 发现行，链接到 AGENT-INDEX.md
  - 幂等：跳过已有文件并警告，绝不覆盖
  - 完成后打印后续步骤

- [ ] **T-002** — 创建 `QUICKSTART.md`（15 分钟入门可视化指南）
  - 以代码块形式展示带注释的终端步骤（尽量避免 PNG 截图，优先使用 ASCII 或 Mermaid）
  - 记录哪些命令产生了每个可视化内容，以便重新截取

- [ ] **T-003** — 为全部 10 个模块 README 添加难度徽章
  - 格式：在每个模块 README 顶部添加 `> 🟢 **Beginner** | ⏱ 30 minutes`
  - 在徽章下方添加"你将构建什么"的要点预览

### 支柱 7：活的课程体系

- [ ] **T-004** — 创建 `WHATS-NEW.md`
  - 格式：`## CC vX.X — DATE`，每个功能变更对应一条要点
  - 至少为当前 CC 版本添加一个条目

- [ ] **T-005** — 为全部 10 个模块 README 添加版本徽章
  - 格式：`> ✅ Verified against Claude Code **vX.X.X** · Last verified: YYYY-MM-DD`
  - 在每个模块的 frontmatter 中添加 `cc_version_verified`

- [ ] **T-006** — 创建 `.github/workflows/staleness-check.yml`
  - 计划：每周一 09:00 UTC
  - 从 frontmatter 读取每个模块的 `last_verified` 日期（使用 `yq` 或 10 行 Python 脚本）
  - 为任何 30 天以上未验证的模块创建 GitHub Issue
  - 如果已存在同名标题的 open issue 则跳过

### 支柱 6：内容质量（CLAUDE.md）

- [ ] **T-007** — 创建项目根目录 `CLAUDE.md`
  - 以项目自身配置展示最佳实践
  - 记录贡献规范、模块结构和维护工作流

### 支柱 2：AI Agent 索引（生成器）

- [ ] **T-008** — 编写 `scripts/build-agent-index.py`
  - 读取全部 10 个模块 README 文件
  - 提取：标题（→ 主题）、代码块（→ 带语言标签的示例）、表格（→ 参考数据）
  - 输出 `agent-manifest.json`，schema 定义见 CEO 计划
  - 输出 `AGENT-INDEX.md`（人类可读摘要）
  - 验证引用指向实际文件

### 模块 08-checkpoints：全面深度改造（311 → 800+ 行）

- [ ] **T-009** — 用真实场景重写模块导言
  - 示例："你的重构刚刚搞坏了 3 个东西。以下是 checkpoints 如何拯救你的……"

- [ ] **T-010** — 添加 checkpoint 策略决策树（Mermaid 流程图）
  - "我想做 X" → 沿箭头走 → 到达 checkpoint 模式

- [ ] **T-011** — 添加 3 个工作流模板
  - 安全重构工作流
  - 使用 checkpoints 的 A/B 测试
  - 灾难恢复工作流

- [ ] **T-012** — 添加与 planning 模式集成的章节

- [ ] **T-013** — 添加 checkpoint 生命周期 Mermaid 图

- [ ] **T-014** — 添加 2+ 个"动手试试"模块，包含可验证命令
  - 每个包含：上下文说明、要运行的命令、预期输出描述

- [ ] **T-015** — 添加"模式与配方"章节，含 2+ 个命名模式
  - 每个模式：问题、解决方案代码、适用场景、不适用场景

### 模块 06-hooks：全面深度改造

- [ ] **T-016** — 用真实场景重写模块导言
  - 示例："你的 CI 在 20 分钟后才发现 lint 错误。Hooks 只需 2 秒就能捕获……"

- [ ] **T-017** — 添加 hooks 决策树（Mermaid 流程图）
  - "当 Y 发生时我想触发 X" → 沿箭头走 → 到达 hook 类型

- [ ] **T-018** — 添加 5 个完整 hook 示例及完整脚本（每个约 80 行）

- [ ] **T-019** — 添加 2+ 个"动手试试"模块，包含可验证命令

- [ ] **T-020** — 添加"模式与配方"章节，含 2+ 个命名模式
